# CropDisease AI — Flutter Mobile App: Full Setup Guide

This turns your Flask web app into a native Android app with the same
green branding, same login/register/OTP flow, same disease detection,
history, disease library, profile, and admin dashboard — talking to the
**same Flask backend** you already built. No second backend is needed.

---

## 0. What you already have vs. what's new

- Your Flask backend (`backend/app.py` etc.) — **unchanged**, keeps running on port 5000.
- A new folder `flutter_app/` (attached) containing a full `lib/` source tree,
  `pubspec.yaml`, and this guide. You will drop these into a fresh Flutter
  project shell (Flutter itself generates the `android/`, `ios/`, `build/`
  folders — those aren't included here because they're machine-generated).

---

## 1. Install Flutter SDK (skip if already installed)

**Windows:**
1. Download the Flutter SDK zip: https://docs.flutter.dev/get-started/install/windows
2. Extract to `C:\src\flutter` (avoid paths with spaces, avoid `Program Files`).
3. Add `C:\src\flutter\bin` to your **PATH** environment variable.
4. Install **Android Studio** (needed for the Android SDK + emulator, even if
   you write code in VS Code): https://developer.android.com/studio
5. In Android Studio → More Actions → SDK Manager, install:
   - Android SDK Platform (latest)
   - Android SDK Build-Tools
   - Android SDK Command-line Tools
   - Android Emulator + an AVD (e.g. Pixel 6, API 34)
6. Open a terminal and run:
   ```
   flutter doctor
   ```
   Fix anything it flags with a ✗ (commonly: accept Android licenses with
   `flutter doctor --android-licenses`).

Verify:
```
flutter --version
```

## 5. Add Android permissions (required)

Open the provided `ANDROID_PERMISSIONS.txt` and apply the two changes to
`android/app/src/main/AndroidManifest.xml`:
- Camera / internet / media permissions
- `android:usesCleartextTraffic="true"` on the `<application>` tag — **this
  is required** because your Flask backend runs on plain HTTP, and Android
  9+ blocks non-HTTPS calls by default without this flag.

Also confirm `minSdkVersion` is **23+** in `android/app/build.gradle`
(needed by `image_picker`).

---

## 6. Point the app at your Flask backend

Open `lib/core/api_config.dart`. This is the **only file you need to edit**
to connect the app to your backend. There are 3 scenarios:

| You're testing on...            | Set `baseUrl` to                          | Why |
|----------------------------------|--------------------------------------------|-----|
| Android **emulator** (AVD)       | `http://10.0.2.2:5000`                     | `10.0.2.2` is the emulator's alias for your PC's `localhost` — `localhost` inside the emulator means the emulator itself, not your PC. |
| Real **phone** on same Wi-Fi     | `http://<your-PC-LAN-IP>:5000`             | Find your IP with `ipconfig` (Windows) → look for IPv4 Address, e.g. `192.168.1.42`. Your phone and PC must be on the same network, and Windows Firewall must allow inbound TCP on port 5000. |
| Deployed backend (later)         | `https://your-deployed-domain.com`          | Once you host the Flask API somewhere with HTTPS. |

The file already has all 3 pre-filled as constants — just change which one
`baseUrl` points to (default is set to the emulator option).

---

## 7. Start your Flask backend

In your web app folder:
```
cd backend
python app.py
```
Make sure it prints `Server running at: http://localhost:5000` — the app
already binds to `0.0.0.0` so it's reachable from the emulator/phone too.

If testing on a **real device**, also allow Flask through Windows Firewall:
```
netsh advfirewall firewall add rule name="Flask5000" dir=in action=allow protocol=TCP localport=5000
```

## 8. Run the Flutter app

Start your emulator (Android Studio → Device Manager → ▶) or plug in a
phone with USB debugging enabled, then:
```
flutter devices        # confirm your device/emulator is listed
flutter run
```

You should land on the green splash screen → login screen. Try:
- **Register** → check your Flask terminal for the printed OTP (since
  `EMAIL_PASSWORD` may not be configured, the backend prints the OTP to
  console as a fallback — see `send_email()` in `auth.py`).
- Enter the OTP on the verify screen → redirected to Login.
- **Login** with the admin seed account printed by `app.py` on first run
  (`bikram204sharma@gmail.com` / `Admin@123`) to see the Admin dashboard,
  or register a normal user to see the farmer dashboard.
- **Scan a leaf** (camera or gallery) → see the AI result screen.
- Check **History**, **Disease library**, and **Profile** tabs.

## 9. Common issues

| Symptom | Fix |
|---|---|
| `SocketException: Connection refused` | Wrong `baseUrl` for your test target — see step 6 table. |
| Requests hang / timeout on real device | PC firewall blocking port 5000, or phone not on same Wi-Fi. |
| `CleartextNotPermittedException` | You skipped step 5 — add `usesCleartextTraffic="true"`. |
| Camera picker returns nothing | Permissions not granted — check step 5, and that you accepted the runtime permission prompt on-device. |
| 401 right after login on next request | JWT access token expires after 20 minutes (matches your Flask config) — this app doesn't auto-refresh yet; log out and back in, or extend `refresh()` wiring in `auth_provider.dart` if you want silent refresh. |
| Images (scan photos, profile pics) don't load | Check `ApiConfig.resolveImage()` — it prefixes relative paths like `/uploads/...` with `baseUrl`; confirm `baseUrl` is reachable from the device. |

## 10. Build a release APK (to install on any phone / share for testing)

```
flutter build apk --release
```
Output: `build/app/outputs/flutter-apk/app-release.apk`

Copy that file to a phone and install it directly (enable "Install from
unknown sources" if prompted). Before building the release APK, make sure
`api_config.dart`'s `baseUrl` points to something reachable by whoever
installs it — usually your LAN IP for local demos, or your deployed HTTPS
URL for anything shared outside your network.

For a smaller app-store-ready build split by CPU architecture:
```
flutter build apk --release --split-per-abi
```

web app's `LangManager` — would need a `LocaleProvider` + `.arb` files).
